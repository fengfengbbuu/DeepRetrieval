要求：
- 保留 REF_FILE 的所有功能。
- 支持参数传递，包括：
    - 模型方面：
        - `model_name`: 模型名称
        - `base_url`: 模型 url 地址
        - `api_key`: api key
    - 数据方面：
        - `test_set_path`: 测试集地址。最好是 `.jsonl` 文件
        - `prompt_key`: 模型 input 对应的 key，默认值参考 REF_FILE（看它是怎么得到 input 的）。
        - `sample_num`: 抽取指定个数的样例进行测试，默认值为 -1，表示处理所有样例。
        - `db_path_key`: 数据库路径对应的字段名，如果是 `key1.key2` 暗示该字段对应的 value 很可能是一个字典，需要访问 key1 然后在访问 key2 才能获取到 database path。默认值为 `extra_info.db_path`
        - `ground_truth_key`: 标准答案对应字段名，如果是 `key1.key2` 暗示该字段对应的 value 很可能是一个字典，需要访问 key1 然后在访问 key2 才能获取到 ground truth。默认值为 `reward_model.ground_truth.target`
        - `failed_file_path` 失败的文件路径（通常是 jsonl 文件），默认为 None。如果存在，程序需要加载该文件内容，并清空该文件的原有内容，抽取所有失败样例的 idx，得到 `failed_idx_lst`，之后对 sample 得到的数据用 `failed_idx_lst` 做过滤，之后的程序仅对这部分过滤后的数据做处理。
    - 实验方面：
        - `with_cot`: true 或 false。表示输入数据是否涉及 cot 内容。（一个 flag）
- 有专门的参数解析函数。
- 数据解析：（最好与其它模块解耦，独立出来）
    - 支持 `.parquet` 的 `test_set_path` 数据解析。
- 测试结果存储格式：在 REF_FIILE 基础上，添加 db path，ground truth 信息。
- 测试结果保存在 `outputs/no_training/spider/zero-shot/{model_name}/{date}` 文件夹下。`{date}` 是程序运行时的时间，格式为 `yyyy-mm-dd`。
    - 文件名格式：`{test_name}.{cot_info}.{sample_info}.jsonl`
        - `{test_name}`: `test_set_path` 的文件名
        - `{cot_info}`: `with_cot` 为 True 是，值为 "wcot"，为 False 时，值为 "wocot"
        - `{sample_info}`: 如果 `sample_num` 为 -1，值为 "all"，否则为 `f"sample{sample_num}"`
    - 另外在该文件夹下以 `args.yaml` yaml 格式保存程序运行的配置信息（主要是参数信息）。
